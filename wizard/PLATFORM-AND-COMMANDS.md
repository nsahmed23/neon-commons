# Runtime, shell, and interaction decision

Choose Python 3.11+ for the small offline helper: stdlib JSON/hash/path/subprocess argument handling, portable source distribution, and a small optional validation toolchain (PyYAML 6.0.3, jsonschema as recorded in verification environment). No separate LLM client, paid API, Go build, full-screen TUI, WSL or administrator requirement for offline source generation. Existing Claude Code/Codex supplies conversation. Do not bundle provider executables.

Reference actually tested: Python 3.13 Linux and Bash argv roundtrip. Windows source execution and native PowerShell are not run here. Shell floor: PowerShell 7.3+ Standard native argument passing; Linux Bash4+ target. Windows PowerShell5.1 is NOT an executable-command target for these renderers; offer emitted text or a separate qualified renderer instead of pretending parity. WSL is relevant to a later host-evaluation sandbox, not ordinary generator operation.

Reference CLI: `python tools/build-reference.py --input <synthetic-export> --context <context.json> --output <new-directory>`. stdout emits one JSON result, stderr errors, no terminal control characters from untrusted values. Exit0 complete offline mapping; exit2 partial review-only generation; exit3 invalid input/precondition; exit4 local output conflict. EOF and Ctrl+C in the eventual host workflow suspend/cancel without an external command. The reference CLI is deterministic and noninteractive; the interactive product is still to be built from the closed graph and transcripts.

Commands are data: executable + exact argv + cwd + effects + target + provenance + approval classification. Render with shlex.quote for Bash, and literal string/array splatting with doubled apostrophes in PowerShell. Never invoke eval/Invoke-Expression. The helper does not execute emitted operations. Reject C0/C1/newline/CR/bidi controls, invalid executable names, and unsupported shells. Paths with spaces/quotes/dollar/brackets/Unicode are accepted as literal argv; leading dashes are safe only where the selected tool's argument grammar permits them. Use `--` when supported, otherwise reject an ambiguous positional value. Tool-specific semantic flags need validation beyond quoting.

Use `argv-vectors.json` and actual Bash echo-argv tests. Native PowerShell execution is explicitly not_run; a future Windows test must spawn a trusted native argv dumper and compare decoded arrays, not merely parse the string. PS output preserves `$LASTEXITCODE`; Bash captures status instead of losing it through pipelines. A planned OpenTofu detailed exitcode2 is a result classification, not universal failure. No generated script installs dependencies, signs in, or elevates.

On execution in a future approved runner, resolve and attest absolute executables; compare source/revision/dirty/provider/engine/Atmos/target/cohort/plan digests immediately before action. Intercept cancellable subprocess groups and reconcile any ambiguous remote operation before retry. Do not present emitted import cards as evidence that an import happened.
