# Product completion audit — Intune IaC v0.2.0

Audited baseline: commit `77682f84022232569418e6ff4e678f2cf06246de` in `intune-iac-plugin`. This is an independent product/documentation review, not a fresh blinded behavioral benchmark or a cloud qualification run. Evidence: implementation modules, operational skill, current and historical docs, tests, and saved `verification/plugin-0.2/` receipts. No percentages are assigned: the intended estate, supported families and release acceptance denominator are not yet bounded.

## Assessment

This is an engineering alpha with a working local inspection and candidate-authoring path. It is not a release candidate for production brownfield adoption. Substantial implementation is still required, even if all existing tests pass. Native execution and tenant access are additional gates, not the only unfinished work.

The largest functional discontinuity is between a candidate proposal and adopting an existing Intune policy under an existing Atmos/OpenTofu backend. The present code has no protected external execution adapter, no authenticated target/backend/approver binding, no verified ownership discovery and no production import/no-change path. Its production mapping accepts one fixed choice setting and direct group targeting. The semantic graph records structural configuration evidence; it does not establish effective users/devices, resolved cross-stack execution identities, or the current state owner.

## Static evaluator interpretation

The saved deferred estimate is 144,591 tokens, of which 95,182 are Python source and 18,291 are docs. These files are executable dependencies/on-demand references, not proof of a 144k-token prompt. The static estimate is useful for packaging review but cannot establish actual host context cost. The skill body itself is 1,234 estimated tokens and the total invocation ceiling is 1,493; reducing repeated text and fixing branching is actionable. The reported cyclomatic maximum of 485 is not established as a single-function measurement: installed `src/evaluators/python.js` lines 101–102 initialize the function maximum from a whole-file decision count. Actual functions still warrant maintainability work: baseline `wizard.run_wizard` is 397 lines and `graph._validate_graph` is 165 lines. Refactor under meaningful regression/mutation tests without sharing derivation code between producer and preservation oracle.

Missing test files in the runtime is intentional distribution separation, not evidence that no tests exist. The source distribution contains the current tests. Native loading and a task-level behavioral evaluation remain necessary regardless of a future static score.

## Ordered completion path

1. Repair the audit's reproducible local correctness, confidentiality and instruction failures; retain negative regressions and publish an accurately labeled development build.
2. Make the narrow production slice provider-valid: finish selected dependency/serializer/pagination qualification, run native schema validation on a suitable host, and test state/config/request roundtrips with a controlled adapter.
3. Complete the narrow adoption product: authenticated collection identity, reference/ownership resolution, native effective Atmos/backend identity, protected import/plan adapter and typed approval/reconciliation. Add failures as first-class results before exposing mutations.
4. Qualify a controlled test tenant: existing-policy import and zero-change plan; exact assignment semantics; concurrent modification and partial policy/assignment failure recovery. Promote only the evidenced resource/host/backend combination to pilot support.
5. Expand against a named estate coverage manifest, not an unspecified promise of all Intune. Add remaining setting polymorphs, exporters, broader families/diagnostics, native hosts/platforms and CI rollout operations with evidence per capability.
6. Publish with real owner/policies, artifact/dependency integrity, operational telemetry/redaction, support/update/rollback practices, and independent host behavioral evaluation. Calibrate CLM separately if it is used for advisory prioritization; it is not a prerequisite for deterministic preservation or an execution approver.

There is no defensible calendar estimate without the first provider roundtrip and a declared estate coverage target. The native IPC limitation blocks an observed provider result here, but does not block engineering steps 1 and much of 2–3. A single favorable tenant smoke test would not finish the broader product.
