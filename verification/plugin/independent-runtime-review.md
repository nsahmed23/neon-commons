## Concrete finding, corrected during review

**MCP falsely marked failed local operations as successful tool calls.** At `intune_iac/mcp.py`, the `tools/call` result originally set `isError` only for `error`, `rejected`, `failed`, and `outcome_unknown`. A real `intune_run_local` generation request against an existing unowned directory returns runner status `failed_no_effect_verified` and `output_conflict`, preserves the directory, and receives CLI exit code 4, but previously received MCP `isError: false`. An existing target lock similarly returns `needs_review` (CLI exit code 2) while previously receiving `isError: false`. This could cause a host to regard a rejected operation as completed. The root agent corrected the failure-status set and added a real stdio regression, `test_mcp_preserved_output_conflict_is_tool_error`; I verified that test passes on the updated files.
