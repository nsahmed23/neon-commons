# Bounded export and normalization contract

The root intake envelope remains version 1.0.0. Correction schemas define strict observed policy/settings/assignments and a separate provider configuration projection. Field-rule records use rule_version 2.0.0; session persistence is schema version 2.0.0. These are local synthetic contracts, not official Microsoft export schemas. Prior normalized files must be regenerated and independently checked; sessions with unknown or old versions enter recovery.

The parser rejects duplicate JSON keys, floating/nonfinite values, integers outside ±(2^53−1), nesting beyond 64 levels and input above 16 MiB. Policy, settings and assignment captures have separate coverage. Completeness requires the independently expected root URL without continuation/filter/projection, GET/successful response, no error member, correctly linked full nextLink values and a complete final page. Missing pages, loops, wrong origin/owner, duplicate references and denied collections block active generation. This does not establish authentic, current or transactionally consistent capture.

Normalization selects exactly one policy by its stable ID. The current capability map admits only the worked Windows/MDM non-template location setting definition and declared values. Missing none-template evidence, malformed polymorphic values, unsupported definitions or unresolved references block active generation. Settings retain their validated IDs and ordered settingInstance structure. The provider configuration removes only the validated outer record discriminator; observation, configuration, request and state remain separate concepts. No refreshed-provider equivalence is asserted.

Stable keys are p_<normalized tenant UUID>_<policy UUID>. Source values, reference IDs, assignment targeting/exclusions/filters and required external references are preserved. Setting/child array order remains significant. Assignment equality uses target tuples; duplicate targets block. Required absent, null and empty values are validated separately. Invalid or unsupported values are kept only in restricted original input; model-visible output contains opaque finding references, reasons and blockers.

Every source node receives an explicit disposition, versioned rule and destination mapping. Retained/secret nodes use an opaque finding ID and restricted-source locator; their raw keys and values are not echoed. This is a bounded retention policy, not a general secret-scanning guarantee for arbitrary production data.

reference/invariants.py independently reparses raw source, derives identity/digests, typed projections, coverage, field rules and external references, then compares actual normalized output. When generated files are supplied it parses actual HCL/import blocks and verifies their source-derived values and guards. It does not import the normalizer/generator or producer field-accounting helpers. The CLI runs this gate before writing, includes a raw-byte plus canonical-source receipt, and emits only inactive review artifacts for partial input.

Expected outputs are locally generated fixtures, never provider-produced plans. Actual provider-schema/SDK/state and tenant qualification remain open.
