# Inactive native repository intent and bounded source proposal

The qualification-only `scripts/intune-windows-source.py` connects native private repository reads to the existing repository-intent and source-proposal engine. The ordinary Windows host profile remains unsupported. The import/proposal commands described here do not modify authoritative source. The same qualification-only CLI now also exposes the separately reviewed local source edit/recovery routes in [WINDOWS-SOURCE-EDIT-R4.md](WINDOWS-SOURCE-EDIT-R4.md); no route here executes Git, provider, plan, backend or tenant operations.

`repository-import` captures exact literal resolved inputs and source bytes for the selected DOS root/stack/component, immutable tenant/object, pointer, declared backend and resource address. The historical revision is explicitly caller asserted: no Git authentication is invented. The immutable native source snapshot records held current root identity and read interval before its store transaction. Later views keep this historical intent separate from current bytes and observed service state. A stored root binding can be compared with a current handle observation without becoming an authenticated historical audit anchor.

`source-acceptance-propose` accepts exactly one supported top-level policy field and requires a complete fresh observation, unchanged source resolution, a matching recorded native root, an exact winning source value and a complete bounded search for shared inheritance impact. It uses the same literal resolver, pointer checks, YAML rendering and dependency-impact code as the existing POSIX route. It writes a NEW private proposal directory outside both source and store. The directory contains original bytes, rendered candidate, complete diff and a manifest with exact hashes/root/file identities and proposal digest. Failed partial output is retained; it is not a complete proposal. The authoritative source and store database stay unchanged during proposal creation.

Review the whole diff: YAML rendering can change comments/formatting. `fresh_plan_required` and `normal_change_review_required` remain true; `no_resource_changes_established`, `source_modified` and `refresh_only_apply_performed` remain false. A proposed source edit does not establish tenant convergence. The native reviewed edit/CAS/recovery route is now implemented separately; it is never silently performed by import/proposal. Its explicit local acknowledgment does not authorize protected execution.

## Actual entrypoints

```text
python -B scripts/intune-windows-source.py --qualification-only --store C:\Pilot\Private\store --tenant TENANT repository-import --repo C:\Pilot\Private\repository --stack deploy/pilot --component intune --object OBJECT --pointer /vars/policy --revision FORTY_HEX_REVISION --backend DECLARED_BACKEND --resource-address policy.one
python -B scripts/intune-windows-source.py --qualification-only --store C:\Pilot\Private\store --tenant TENANT source-acceptance-propose --object OBJECT --field /description --output C:\Pilot\Private\new-proposal
```

The shared text Workspace also accepts `repository-import REPO STACK COMPONENT OBJECT POINTER REVISION BACKEND RESOURCE_ADDRESS` and, after selecting an observed immutable ID, `source-acceptance-propose FIELD NEW_OUTPUT_DIR`. Use single quotes around DOS paths/spaces in that Workspace's existing shlex grammar. The readonly inspection CLI remains readonly. Native live activation and native terminal/shell qualification are separate gates.

## Independent native procedure

Prepare an authorized disposable native private NTFS checkout and a native store with an independently captured complete observation. Preserve source originals. Independently author an expected JSON containing exactly `source_path`, `before_sha256`, `after_sha256`, `affected_stacks`, `source_pointer`; these must express literal expected bytes and impact, not values generated by the product under test. Pin its bytes. Independently pin every file in the qualifier's `FILES` plus source commit in `{"source_commit":"...","files":{...}}`, and verify Git/source linkage separately.

Run `python -B scripts/qualify-windows-source.py --help` for the required exact arguments. Supply the declared store/tenant/repository/stack/component/object/pointer/revision/backend/resource-address, field, NEW proposal directory, independently pinned expected JSON, source-pins and NEW private evidence output. The qualifier executes actual native source CLI import and proposal commands, retains stdout/stderr/exits, checks before/after expected source bytes and shared impacts, and checks that original source stayed unchanged. It never calls cloud services or edits source.

Repeat using separately pinned fixtures for inherited fields, settings/ordered arrays, assignments/exclusions/filters, null and explicit unknown/unsupported values. Wrong pointers, denied/incomplete observation, changed source/root, invalid field, an in-repository output, output collisions and failed publication barriers must preserve rejection/partial evidence. Actual native Windows ACL/reparse/namespace/SQLite behavior, Git Bash/mintty/PowerShell, runtime dependencies and power-loss handling remain required platform gates. Linux recorded Win32 controls and real SQLite/source tests do not satisfy them.
