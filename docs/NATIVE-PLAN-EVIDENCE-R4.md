# Native no-change output evidence

The shared helper accepts the declared OpenTofu 1.13.1/provider 1.0.0 fixed resource
representation only. `capture()` preserves exact raw binary, JSON and exit bytes
with guarded owner-private regular-file reads and exclusive durable archives.
The receipt binds the completed host-result digest; initial adoption and recovery
Plan outcomes store it before exposing their result. `qualify()` rechecks both
copies, exit0, full identity/value/assignment parity with supplied receiving-state
bytes, and literal source/configuration parity. It grants no receiving-state,
execution, signing, recovery or ownership authority.

Both callers supply freshly authenticated sealed receiving-state proof separately.
Original state/source hashes and exact JSON types are required. Initial completion
pins expected hashes from the durable capture, so a second read cannot bless
changed artifacts. The final SQLite ownership transaction rechecks artifact,
source/state and durable capture identities. Recording failure/cancellation keeps
known host cleanup, an unknown result, original ownership and the spent attempt;
no automatic import, Plan or apply replay occurs.

The original no-op parser accepted wrong ID, changed description and assignment
filter mutants. The stricter candidate then exposed Python boolean/number equality;
both before receipts remain in `independent/adoption-recovery-plan-artifact-before-01`
and `independent/plan-content-before-01`. Independent after content and archive
receipts are separate overlapping assertion scopes, not extra native executions.
Historical native output is replayed as content only. Final-package native
qualification is still required for both changed application routes.
