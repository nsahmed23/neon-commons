# Security assurance — completion increment

This is a scoped independent security review with local regression evidence. It is not enterprise acceptance, a complete Cloudflare audit run, or a claim of zero vulnerabilities. The runtime remains limited to the supported local/synthetic profile documented by the product; authentic Graph/provider/backend mutation and organizational approval are separate gates.

Start with `research/completion/security/findings-ledger.json`, `threat-control-evidence.csv`, `composed-cases.json`, and `sandbox-regressions-frozen.json`. Findings have explicit lifecycle states; a source hypothesis without a demonstrated boundary result has no severity. Historical `verification/enterprise-0.3/security/` evidence is retained as historical, not silently treated as a current run.

## Boundary and attacker model

The operator controls the installed application, launch configuration, trust roots and authorized filesystem capabilities. The model is potentially hostile. Imported Graph records, policy descriptions, names, errors, YAML/HCL, saved sessions, proposed tool arguments and external skill/tool documentation are data. An untrusted contributor can change a repository presented for analysis. A lower-privileged local actor may control a shared directory; that is materially different from the trusted operator intentionally selecting a path. A compromised dependency, provider or executable can exercise its process authority, so pinning and isolation are separate requirements.

Protected assets are capture confidentiality; settings and targeting fidelity; credential audience; tenant/principal/backend identity; exact saved plan and executable identity; approval intent, expiry and single consumption; operation history; availability; and trustworthy evidence. The four principal domains are the operator/model host, the read-only analysis process, the local test executor, and future Graph/provider/backend principals. No skill, Wally result, model response or locally supplied target JSON grants the last domain's authority.

The source-visible flow is CLI or MCP request → bounded parsers → capture/target/repository normalization → independent preservation checks → generated candidate files → local plan/recovery adapters. MCP now requires an operator-created filesystem capability. Generated production candidates are inactive. The local native adapter accepts an output-only OpenTofu fixture and must preserve its hardcoded executable/configuration limits; it is not a general plan runner.

| Entry or durable surface | Boundary and control | Important remaining assumption |
|---|---|---|
| `cli.py`, `mcp.py` tool names and arguments | Static tool vocabulary; schema checks; server-side read/write roots | Host owns launch arguments and installed source; direct Python access is trusted operator authority |
| `io.py`, `engine.py`, `reference/core.py` JSON and project files | Regular-file and size checks; duplicate-key rejection; independent preservation; private generated modes | General runtime filesystem remains cooperative; descriptor-safe capture persistence is stronger than ordinary path checks |
| `capture.py` Graph pages and token | Fixed HTTPS origin/path; no redirects or proxy fallback; page/byte/elapsed limits; raw capture receipts | Token is explicitly supplied; capture tenant label is not authenticated tenant evidence; DNS/TLS/OS trust is external |
| `repository.py`, `atmos.py` repository and stack inputs | Inert bounded literal parsing; reject aliases, templates and unsupported features | Native Atmos execution must separately exclude hooks, workflows, custom commands and environment overrides |
| `target.py` identity/backend claims | Strict relationships, freshness, endpoint comparison; claimed versus observed distinction | Incomplete authentication and backend observation remain release blockers for live operation |
| `runner.py`, `execution.py`, `protected.py`, `journey.py` | Exact adapter types, hash binding, exclusive local locks, started-before-effect journals, independent readback | Local locks are cooperative; no claim to fence Graph administrators or other state backends |
| `judge.py`, model/skill/tool output | Advisory only; fixed endpoint policy; output schema | Reviewer can be wrong or manipulated; it cannot authenticate or authorize |
| wheelhouse, source catalogs, CI and packaging | Exact acquisition manifests and dependency lock hashes | Hash consistency is not publisher authentication; current vulnerability advisories and AppSec remain separate |

The guarantees do not survive compromise of the operator OS account, runner/kernel, Python runtime, trusted installation, credential store or approval service. A malicious same-privilege process can change source, syscall behavior, clocks, keys and evidence. The in-process synthetic grant is deliberately not an enterprise approval service. Tamper-evident local hashes do not prove who wrote them.

## Reproductions and fixes

The independent reviewer identified ambient capture proxy selection, missing MCP filesystem authority, a sibling-lock write outside the granted output root, and executable self-pinning in synthetic recovery. The implementation owners repaired product code separately. Red/green evidence and current source traces are in the findings ledger. Template evaluation in native fixture strings was additionally challenged; initialization was already being guarded, and persisted configuration received the corresponding validation.

`scripts/security-audit-local.py` inventories Python imports and sensitive sinks without importing target modules, retains parse failures and skipped scopes, and validates ledger evidence structure. Its static matches are candidates, not confirmed vulnerabilities. Self-tests include deliberately executable source, parse failure, symlink exclusion, secret-canary non-disclosure and invalid confirmation records. The hostile-model test deliberately requests unknown commands, cloud apply, out-of-scope reads and forged approvals, and observes zero dispatches or filesystem changes.

The fixed sandbox command runs the independent corpus and owner security regressions with read-only source/toolchain, no host writable mounts, an empty allowlisted environment, new network/PID/user namespaces, dropped capabilities, bounded tmpfs storage and process/CPU/memory/file/wall limits. It checks an actual denied source write, absent host `/etc`/`proc` and unreachable TEST-NET destination. No target credential or live endpoint is used. Output is captured through pre-opened bounded files and promoted only by trusted parent code after the process exits; arbitrary scratch trees are never copied.

```bash
python scripts/security-audit-local.py inventory --root intune_iac
python scripts/security-audit-local.py validate-ledger --input research/completion/security/findings-ledger.json
python scripts/security-audit-local.py sandbox-regressions --root .
python -m unittest plugin_tests.test_security_audit_completion -v
```

Use the pinned dependency environment for the last two commands. The sandbox command fails closed when Linux/bubblewrap namespaces are unavailable. The first attempted run lacked `jsonschema`; a later expanded run hit the one-megabyte fixture file cap while copying the pinned 31 MB interpreter. Both raw failed records are retained and classified as infrastructure failures, not vulnerability evidence. The 16-test run explicitly allows 64 MiB files and retains at most one MiB per output stream; truncation fails the run. It passed 16 fixed tests with an observed sandbox probe. Native subprocess tests that require procfs are not covered by this minimal sandbox, whose procfs mount is unavailable. Windows ACLs, PowerShell, host integration, real provider RPC and live tenant behavior need their own evidence.

## Release decisions and operational response

Enterprise release remains BLOCKED on authentic target/backend/provider lifecycle evidence, AppSec review, authorized pilot, unsupported hosts and unresolved credible high-impact paths. A passed fixture suite does not remove these gates. Each residual risk must receive a real accountable organizational owner, rationale, compensating control and review date; this report leaves unassigned owner fields explicit rather than inventing approval.

For suspected credential exposure: stop the affected job, preserve bounded protected receipts, revoke the specific token/client credential or federation trust through the authorized identity owner, rotate the affected secret/certificate, invalidate pending approvals and reobserve both Graph and backend principals. Do not copy raw plans/state/tokens into model prompts or support bundles. Review service audit records and identify affected tenants, objects, blob versions and time windows before restarting.

For interrupted mutation: retain the lock and started event; classify unknown until independent authenticated readback and backend revision observations succeed. Compare policy and assignment facets separately. A successful policy write with failed assignment write is partial, and restored state is not restored infrastructure. Do not blindly retry or automatically delete the lock. A new operator decision must bind fresh observations and a new exact plan.

At every release and dependency/provider/skill/model/permission/cloud change, rerun integrity and security regressions, review advisories for the exact locked packages and tool versions, re-evaluate affected threat-matrix rows, and invalidate stale qualification. An organizational owner should monitor upstream advisories between releases. No recurring external monitoring task or disclosure has been created by this workstream.
