## Concrete preparation and execution entrypoints

## Evidence handoff and final decision

For every external attempt, bind the exact source commit, source/runtime ZIP hashes, interpreter/native executable/image/library pins, command argv and working directory, run/attempt identity, approved scope, timestamps, raw receipts and the independent assertion source. Keep credentials and restricted tenant/device data in approved private storage; public artifacts require an explicitly suitable allowlist and recorded private omissions. Preserve negative attempts and closed-scope reuse rather than reclassifying or summing overlapping runs.

The full connected acceptance order is: native client discovery/inspection → complete ownership → adoption/import and no-change ordinary plan → intentional authoritative source change → fresh exact-plan approval → protected dispatch while client detached → independently authenticated policy/settings/assignment readback → no-change second plan → separately authorized interruption/reconciliation → scheduled authenticated collection with all terminals closed → representative endpoint evidence. G01–G12 must have their own implementation/evidence/approval status. A completed checkpoint or successful local suite is only a continuation point.
