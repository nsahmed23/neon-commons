# Appendix B correction specification

**Status:** correction contracts and reproduced counterexamples; not an integrated repaired generator. Reviewed 30 September 2026. Preserve the original pack and its receipts. G03/G04/G06 are reopened as partial. The original supported golden must not be called provider-valid.

## 1. Provider projection and bounded semantics (F01/F03)

Use five distinct representations: restricted original bytes; parsed observed records; proposed provider configuration; actual SDK request; refreshed provider state. Each transition requires its own oracle. The original exporter-to-HCL transformation confuses the second and third.

The selected input setting remains in restricted observation as `{id, @odata.type, settingInstance}`. The corrected provider **configuration** record is exactly `{id, settingInstance}`. Preserve the nested type discriminators, definition ID, value and child order. Account for the removed *wrapper* discriminator as validated observed metadata, not as unknown loss. Preserve wrapper ID as configuration identity; it is not merely disposable metadata. See `fixtures/provider-settings.corrected.json` and P01/P02.

The proposed first-slice support rule is IDs `"0"` through `"n-1"` in their original order. Reject missing, nonnumeric, padded, negative or nonsequential IDs for adoption output; do not silently renumber. This is intentionally stricter than the pinned validator: its comment says first ID zero, but the examined implementation checks numeric strings and adjacency only. Likewise it returns early for an empty array; the new nonempty rule is a product boundary, not a claim about that validator.

P02 constructs a fresh SDK setting and does not copy its ID. P11's serializer delegates base fields to Entity and nested data to settingInstance. Therefore configuration ID and wire identity are distinct. **Do not assert an exact wire body until Entity, typed model JSON tags and the pinned Kiota writer are reviewed and an offline serialization test is run.** Choice children are only set by P02 when nonempty; null versus absent and empty children therefore need an explicit roundtrip test.

P03 wraps returned settings and preserves response fields; P04 sorts object keys without stripping fields or reordering arrays. P05 supplies no resource-level semantic reconciliation. Restoring configuration IDs and removing the wrapper discriminator fixes a deterministic shape error in our contract; it does not prove refreshed state matches or suppresses differences correctly. A response containing wrapper `@odata.type` may still produce a representation difference. Do not mask it with `ignore_changes`.

`contracts/observed-*.schema.json` and `provider-settings.schema.json` define a small **local** supported subset: Windows/MDM, nonempty policy settings, choice and simple string/integer instances (recursive choice children), null/absent template references, and group inclusion/exclusion targeting. Group collections, secrets, non-null templates and unknown types remain review-only until qualified. This does not remove them from the product roadmap. A nonempty definition/value string is shape-valid only; the generation capability map must additionally establish the exact definition, permitted value, platform applicability and provider implementation before active output.

Apply checks in order: bounded input size/depth and duplicate-JSON-key rejection; capture validation; selected policy/type validation; discriminator-specific setting shape; per-collection count reconciliation; identity/reference/target validation; provider-specific configuration constraints; normalized schema; independent preservation oracle; generated-artifact validation. No write before these gates. Existing `tools/build-reference.py` checks only intake and must be changed to validate each output contract. Schema failures return codes and safe pointers, never the rejected raw payload.

Description must be a string <=1,500 characters under the local contract; include boundary and Unicode provider-compatibility tests. Group/filter IDs must be full nonzero GUIDs; do not apply a GUID assumption to assignment IDs, which are opaque service IDs. Include/exclude filter mode requires a nonzero filter ID; none mode omits `filter_id` from provider configuration. The pinned schema has a computed/default zero value and an explicit zero-ID validator: qualify default sequencing separately. Preserve source null/absent forms in field accounting. This bounded reference allows exclusion groups only without a filter; an unqualified combination blocks executable output rather than dropping it.

## 2. Complete captures and consistent references (F02/F04)

The collection root is derived from independently validated cloud, API version, selected object ID and a **pinned exporter adapter contract**, never from the first captured URL. For the default adapter:

- Policy inventory begins at `/beta/deviceManagement/configurationPolicies`, with no query. It is complete only for that inventory scope. A selected-policy GET is a different request kind, not a complete global list.
- Settings begin at `/beta/deviceManagement/configurationPolicies/{id}/settings`, with no query.
- Assignments begin at `/beta/deviceManagement/configurationPolicies/{id}/assignments`, with no query.

The public-cloud origin is exactly `https://graph.microsoft.com`; other clouds require explicit adapter definitions. Do not import public-cloud roots into sovereign contexts. A pinned alternative adapter may require `$expand=children` for settings, but that must have a separate reviewed expected root/query contract; the supplied default model deliberately rejects it rather than pretending to reproduce a provider helper.

First request must equal its expected boundary. Initial `$skiptoken`, `$skip`, `$filter`, `$search`, `$select`, `$top` or arbitrary projections are not accepted as a full capture in this adapter. Subsequent requests must equal the preceding response's **entire** nextLink, remain in the allowed service origin and collection path, contain no credentials/fragment/control characters, and avoid prohibited narrowing queries. Detect duplicate URLs/loops, skipped pages, failed or missing response bodies, and a terminal dangling nextLink. Missing nextLink after a valid final page is necessary, not sufficient by itself. W01 supports opaque nextLink following, not capture authenticity.

Require one explicitly scoped collection per required kind/owner, with per-page capture time, status and acquisition provenance. Require successful page bodies with `value` arrays; error/denied/missing pages invalidate completeness. Distinguish an explicitly captured empty assignment set from absent assignment acquisition. Reconcile reported policy settingCount against collected settings, but do not use isAssigned or a global count as proof of full targeting. Duplicate settings/assignment identities, capture gaps and inconsistent observations block executable adoption.

Offline validation proves structural completeness relative to the declared adapter. It cannot prove unedited logs, server authenticity, freshness or an atomic snapshot across policy/settings/assignments. Source permissions and capture timestamps remain part of qualification; a later service read is needed before any reviewed execution.

For references, the correction chooses conservative duplicate rejection, including identical duplicates. No last-write-wins and no implicit newest-timestamp override. A future supersession rule needs verified same tenant/object/version identity, complete successful observations, time/consistency rules, retained conflict evidence and its own tests. Group, filter and scope-tag references remain externally owned. Verify that all required IDs have exactly one unambiguous allowed observation; do not infer permission from a supplied coverage label.

## 3. Independent preservation and retention (F05/F06)

The oracle must not call the generator or normalizer to obtain expected answers. Independently validate capture boundaries and primitive shapes before comparing source to output. Derive selected identity from the validated context, never from the produced normalized object's ID. Compute the stable key from validated tenant+policy IDs, using the existing explicit `p_` + UUID-hex rule or a separately versioned replacement; a display-name edit must not alter it.

Recompute two different digests: raw-source byte SHA256 in the restricted evidence store, and a versioned canonical parsed-source digest for semantic comparison. Do not substitute one for the other. Define canonicalization and reject duplicate object keys, NaN/infinities and unsupported numeric ranges before hashing. The source digest used by the existing pack is compact UTF-8 sorted-key JSON; preserving that convention requires explicit version1 compatibility, not a claim it implements RFC8785/JCS. Avoid cross-language float ambiguity by excluding floats in the bounded fixture. Input filenames or a supplied digest are not evidence of contents.

Independently derive every emitted desired field: name, description, platform, technologies, scope tags, settings IDs/values/child order, assignments and filters. Derive all required external reference identities and ownership; compare with produced reference records, not just desired targets. Verify complete field-accounting entries by expected rule/disposition, not pointer presence alone. Containers and leaves both need one record; each record names the rule/version, destination pointers or retention reason, and loss-blocking status. A broad ancestor rule cannot erase a leaf's required semantics.

Use a small reviewed mapping table (`contracts/field-rules.csv`). Unknown fields fail classification. Derived values need an explicit rule; desired collection deletion is never inferred from absent observations. Parse generated HCL/import data independently using the selected parser/provider schema before production qualification. Compare tenant/family/object ID -> resource key -> resource address -> import ID across normalized records, imports and generated file manifest. A regex or matching file hash alone is not enough to interpret arbitrary HCL.

For F06 choose **no unsupported raw values in normalized/review/model-visible artifacts**. Preserve only safe pointer/opaque finding ID, source-byte digest reference, type name if safe, reason, retention locator, and blocker. Unsupported values remain in the restricted original source. Unknown keys themselves can contain sensitive data; a model-visible derivative uses opaque finding IDs when a pointer would disclose content. The full pointer mapping stays local and restricted. Known desired values may still be sensitive, so this is not a universal sanitizer; secret-bearing types remain unsupported and model access requires approved minimization.

Canary test: insert a unique synthetic marker into an unknown nested field, normalize, render reviews, errors, session, manifests and commands, then assert it appears in none of those bytes; it remains present only in the original fixture. This is evidence for this canary, not a guarantee of all-secret detection. Partial mapping yields review-only artifacts; no active `.tf` or import/plan/apply command cards. Store the supported projected portion in an explicitly inactive review document if useful. A sidecar alone never authorizes partial apply.

## 4. Prerequisite-aware resume (F07)

Use ordered milestones: repository, source, inventory, selection, ownership, mapping, generation, validation, review. UI state names map to a milestone frontier in `contracts/resume-stage-map.json`. A saved state records where work stopped, not authority to skip the earlier tasks. Session v2 records every invalidation fingerprint explicitly, including selected IDs, ownership, provider version/schema, identity, backend identity and plan.

On resume: validate schema/version; independently reacquire current context and artifact receipts; cap claimed completed milestones to those **before the saved frontier**; intersect them with independently verified completion; remove changed milestones and every dependent milestone; take the first missing prerequisite. Unknown/corrupt versions return recovery, not a migration guess. Map complete versus partial generation through a dispatcher. Mapping unknown/blocked clears mapping and later completion. Mapping status is independently recomputed, not trusted from the session.

`models/contract_model.py::resume_decision` is an executable decision specification. Its caller must actually re-read evidence; a list called `verified_completed` supplied by the agent is not verification. Fingerprint origins are specified separately. This model is not wired into the original wizard and does not reconstruct missing source files on its own.

Worked cases: saved object_selection with changed cohort stays at object_selection, assuming earlier receipts remain valid; it does not advance to adoption_preview. Saved partial_generate with changed stack returns partial_generate after valid earlier receipts, never full generate. Saved user_review with missing inventory receipt returns inventory. If any in-flight operation has unknown outcome, return reconciliation_required with no executable action; never replay. Completed local review only yields a qualification handoff, not authentic approval.

Represent suspend/cancel separately from stable saved progress. Save the last nontransient state; the serialization layer must not overwrite it with resume_validation/resume_dispatch. Cancellation must not execute or delete user output. Explicitly resuming a cancelled session requires local intent again and revalidation, not old approval. Session migration and native interruption handling remain integration tasks; they are not closed by graph reachability.

## 5. Target and approval binding (F08)

`contracts/approval-context.schema.json` chooses explicit structured target fields. Bind cloud + service/authority endpoints, tenant, principal object/client identity, authentication kind and federation issuer/subject/audience, target subscription when applicable, full backend identity, component/stack, exact source/config/plan/cohort/ownership/selected-ID digests, Git and relevant dirty inputs, provider lock/source/version, OpenTofu/Atmos version and binary digests. Backend includes type, cloud, tenant, subscription, full storage account resource ID, blob endpoint, container, key, workspace, resolved blob name, and observed lineage/serial. The backend subscription can differ from target subscription; record both.

An Intune-only target subscription is explicitly null, not inferred from the Azure backend. Unknown backend or principal facts cannot produce an executable approval match. Existing adoption expects an existing state identity; an intentional bootstrap with no prior state requires a different schema/operation class. A key alone is not a globally unique state identity. Do not guess how workspace changes the blob path; obtain actual effective backend identity through a version-qualified inspector.

The comparator validates both structures and compares every defined field. It also checks timezone-aware approval and expiry. `fixtures/approval-context.json` contains deliberately synthetic hash-looking strings, not an approval or acquisition receipt. One-field mutation checks cover the complete binding tree. This still does not authenticate the approver, enforce CI policy, establish token claims, or prevent time-of-check/time-of-use races.

Define configuration digest from a sorted manifest of **all relevant input byte hashes** (source code, imported Atmos manifests, HCL/JSON/YAML, generated config, backend and CLI configuration, applicable workflow/hook definitions), canonical resolved non-secret inputs, tool/provider identity and schema versions, operation class and target. Sensitive inputs require approved version references or protected commitments, not exposed raw values or low-entropy unsalted hashes. An independently implemented verifier must re-resolve the same closure. If arbitrary executable hooks or unresolved environment variables prevent a closed manifest, mark the approval unbindable. No omitted field is excused by an undefined aggregate digest.

At execution use protected identity/artifact controls, verify again immediately before action, acquire the appropriate operation/state lock, reject drift or changed state serial where required, and reconcile ambiguous outcomes. A local fingerprint equality is merely a consistency check. Do not persist approval grants in resume state.

## 6. Local output and command recovery (F09)

Treat malformed generated-files.json, invalid structure/paths/digests, and unknown manifest schema as **output ownership conflicts**. Return exit4, preserve every existing byte, and provide a safe recovery report. Do not regenerate ownership metadata to claim user files. The manifest read should translate JSONDecodeError and ownership-schema errors to the same domain-specific OutputConflict; catch that before generic input-error exit3. Stage changes to a separate directory and recheck ownership hash before atomic commit; fsync/rename/filesystem and concurrent writers require native tests.

For emitted Bash, use only registered executable identifiers. Reject assignment-like, control-character, leading-dash and reserved builtin/keyword tokens. Resolve to an approved absolute binary and digest before execution. The supplied `validate_executable` model checks a preview basename only; it does not establish binary trust. Bash `command --` can still invoke builtins and is not an external-only execution boundary. The repaired preview validator uses a registry, while any future execution adapter must resolve approved absolute binaries. No eval or Invoke-Expression. Keep shell argv tests separate from provider execution and native PowerShell qualification.
