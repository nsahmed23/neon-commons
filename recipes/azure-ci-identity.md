# Azure/CI reference and exact remaining adapter boundary

Use `examples/azure-integration/expected/project/`. It contains an actual existing-backend configuration, a complete Atmos policy fixture, and two inactive CI YAML examples. This is a source-backed reference, not a deployed Azure workflow. Backend OIDC/Entra auth fields are documented at https://opentofu.org/docs/v1.10/language/settings/backends/azurerm/ . GitHub federation concepts: https://learn.microsoft.com/en-us/azure/developer/github/connect-from-azure-openid-connect . Checkout v4.2.2 was resolved to commit 11bd71901bbe5b1630ceea73d27597364c9af683.

Organization inputs: repository/branch/environment, tenant/cloud/subscription, existing storage/container/key, backend owner, immutable engine/Atmos/provider pins, provider auth method, private DNS/runner reachability, permissions and retention. No raw token, secret, private key or state required as an input field. Preserve existing state ownership and lineage; no implicit new backend.

Future protected plan job: independently trusted checkout of approved revision; sterile credential environment; validate issuer/subject/audience and actual target; backend-only storage identity; separately scoped Graph reader; invoke version-qualified Atmos plan; retain binary and structured plan privately with revision/config/lock/source/cohort/identity fingerprints. A token decoded without signature/issuer validation is not authenticated identity. Do not log tokens or raw plan values.

Import/apply: require organization approval bound to exact reviewed artifact and context. Compare with `reference/approval.py`, but expected approval must come from an authenticated protected store, not the candidate's files. The comparison is an offline mismatch detector, not a signature verifier or approval grant. Use a separate writer identity and operation-specific policy; no synthetic receipt or locally written acknowledgement can authorize execution. Handle concurrency and stale source/cohort/plan as invalidation; do not replan silently inside apply.

Verify management-plane read-back separately from storage data access and DNS/network reachability. Storage authorization must be scoped to the existing container where practical; exact backend rights depend on lease/read/write/list operations and selected version. No broad Owner grants or public-access workaround. Negative tests: disallow a second container/state key where boundary requires it; wrong tenant/audience; out-of-scope Graph policy; forbidden device action. Record documented scopes separately from observed enforcement.

Unfinished public implementation work: exact selected provider OIDC/config code and full Atmos CLI pass-through/import/plan contract; real action/artifact adapter and signatures/ACLs; dependency/engine schema validation. These are G08/G09 bounded gaps, not implicit capabilities of the template. Live permissions, plan/import and network observations remain separately authorized.
