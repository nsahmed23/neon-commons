# Integrated offline session workflow v2

`tools/session-reference.py` implements `create`, `inspect`, `resume`, `suspend` and `cancel`. Every invocation requires `--offline --root PATH`. Resume additionally requires explicit `--resume` intent. Store creation accepts repeated `--artifact KIND:RELATIVE_PATH`; inspect/resume accept no caller completion list or fingerprint overrides. `reference/workflow.py` is the corresponding Python API. See `examples/workflow-demo/README.md` for copy-ready examples.

The approved root contains `session.json`, `receipt-index.json`, retained source bytes, validated decisions and supporting artifact reports. Session v2 replaces v1; unknown or v1 saved versions return recovery. Rebuild from current evidence with create in a fresh directory to migrate. There is no inferred v1 migration, grant carryover, replay or output deletion. Creation uses an exclusive local writer lock; ordinary concurrent creators cannot both succeed or overwrite metadata. A crashed creation lock blocks a retry; use a fresh evidence directory and reinspection for recovery. Lifecycle updates reject an altered receipt-index hash. Lifecycle in the index is separate from the stable saved state. Transient resume states cannot be saved.

The schema registry is fixed in the inspector. Receipt `schema_id` labels identify the local store protocol (`KIND/2.0.0`), while source/normalized/generated payloads are checked against their registered canonical payload contracts. New report payloads use Draft 2020-12 schemas in `reference/workflow.py::REPORTS`. Identity reports use the complete structured approval binding schema. Unknown kinds/versions, duplicate artifact IDs/kinds/milestones, duplicate JSON keys, floats, nonfinite JSON, unsafe/absolute/traversing paths and symlinks fail closed. Reads are size bounded. Each present artifact is reread and hashed; dependency hashes and prerequisite dependency edges are checked before completion. Every milestone needs all required artifacts plus a receipt containing their identities and every known fingerprint through its frontier. Missing/null/changed prerequisites invalidate its completion.

Repository identity is reconstructed from current HEAD/ref bytes and actual relevant input hashes. Source selection, target pins and actual source locator are reread from a typed local decision artifact. Inventory checks pinned public-cloud collection roots, successful complete chains, duplicate observations, selected-policy count and typed objects. Selected-ID and ownership digests are recomputed from retained decision values. Mapping invokes the independently implemented preservation oracle, checks the actual parsed provider lock version and schema provenance bytes, and compares pinned tool byte identities. Full generation rereads every manifest-listed file, checks its hash, and reruns the oracle over actual generated bytes. Validation repeats this independent check; it never trusts a `passed` field. Review includes current cohort/plan bytes, scope and expiry. Session receipt claims are intersected with this independently reconstructed completion and capped before the saved frontier; partial mapping uses the partial-generation dispatcher.

Structured `reference.approval.mismatches(expected, observed, now)` accepts a complete v2 approval envelope and observed binding or envelope. Both structures are validated, all target/tool/input fields are compared, and aware validity timestamps checked. The correction comparator handles valid object/null identity changes. The legacy flat interface remains for historical tests; supplied cloud/backend/state-key fields are compared too. Legacy equality is not execution authorization. CLI `tools/check-binding.py` uses this integrated comparator and reports `approval_authenticated:false` and `execution_authorized:false`.

The reference supplies local consistency evidence. Developer ownership declarations, source captures, HEAD files and pinned tool version labels are not authenticated acquisitions. Closed effective-input reports remain a version-qualified inspector responsibility; arbitrary executable hooks or unresolved environment inputs require qualification and cannot authorize execution here. Native UI interruption, adversarial concurrent parent-directory replacement, transactional multi-file recovery, actual tool-version acquisition, provider/SDK/state roundtrip, protected approval and tenant execution remain separate gates. No store API or wizard state performs an external effect.
